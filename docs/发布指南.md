# 更新与发布指南

## 先说结论：平时就这三行

在 **Git Bash** 里（Windows 上装 Git 时自带的那个）：

```bash
cd /e/projects/blog/AndySGZ.github.io
git add -A
git commit -m "这次改了什么"
git push
```

推完等半分钟到一分钟，`andysgz.top` 就是新的了。

> 路径要写成 `/e/...` 而不是 `E:\...`——这是 Git Bash 的写法，两种别混着用。

## push 报错了怎么办

| 报错长这样 | 是怎么回事 | 怎么办 |
|---|---|---|
| `TLS connect error: unexpected eof`<br>`Failed to connect to 127.0.0.1 port 7897`<br>或者干脆卡住不动，最后超时 | 你电脑上那个代理（Clash，127.0.0.1:7897）没开或者正在抽风。git 被全局配成了走它，代理一挂，推送就跟着挂 | 见下面「绕过代理」 |
| `Please tell me who you are` | 没配 git 身份 | 这台机器已经配好了，正常不会遇到 |
| `Updates were rejected` | 本地落后于线上（一般是换了台电脑改的） | 先 `git pull` 再 `git push` |

### 绕过代理

这一次单独的推送不走代理，**不会动你的全局配置**：

```bash
git -c http.proxy= -c https.proxy= push origin main
```

这条就是把代理临时清空再推。想每次都省事，也可以把全局的那条代理配置删掉：

```bash
git config --global --unset http.proxy
git config --global --unset https.proxy
```

删掉之后直连 GitHub 也是通的（实测过），而且以后代理开着关着都不影响推送。**要不要删你自己定**，我没替你动。

## 推完之后多久生效

两层缓存，都得等：

1. **GitHub Pages 自己构建**：收到推送后通常 30 秒到 1 分钟
2. **缓存 10 分钟**：GitHub Pages 给所有文件发的都是 `Cache-Control: max-age=600`，
   前面还叠了一层 CDN（Fastly）。所以推完最坏情况是 **10 分钟内你或访客看到的还是旧版**

急着看效果就这么办：

- **硬刷新**：`Ctrl + Shift + R`（Mac 是 `Cmd + Shift + R`）
- **一次性彻底**：`F12` → 在刷新按钮上右键 → 「清空缓存并硬性重新加载」
- **边改边看**：`F12` → Network 面板 → 勾上 `Disable cache`，只要你开着开发者工具就一直不读缓存

### 有个招数在这站上是没用的

给样式表加版本号（`style.css?v=2`）是网上常见的缓存打法，**在这里别用**。

实测过：随便编四个从没请求过的查询串去打线上，返回的 `Age` 全都一模一样、
`X-Cache: HIT`——说明 GitHub Pages 的 CDN **把查询串从缓存键里剔掉了**。
结果是浏览器那边看着像生效了，别人那边可能还在看旧的，反而更难查。

## 怎么确认线上真的是最新版

比一下 md5 就行：

```bash
cd /e/projects/blog/AndySGZ.github.io
md5sum assets/style.css | cut -d' ' -f1
curl -s http://andysgz.top/assets/style.css | md5sum | cut -d' ' -f1
```

两行打印出同一个哈希串，就是已经更新到位了。想查别的文件把文件名换掉即可。

## 推之前跑一下测试

```bash
/tmp/noderun/node-v24.21.0-win-x64/node.exe --test
```

68 条，几秒钟跑完。它盯着的是这些容易悄悄坏掉的东西：

- 六个页面的导航必须完全一致、中英文必须同字号
- 每一页里的每个链接都必须指向真实存在的文件
- 明暗两套 token 必须一字不差（少写一条，关掉 JS 就换了副面孔）
- 正文、辅色、选中态的对比度都得过 WCAG AA（4.5:1）
- 样式表里不许出现 token 之外的颜色字面量
- 不许有圆角、模糊阴影、渐变，倾斜不许超过 3 度

> 你这台机器的 PATH 里没有 node，上面这个是之前下在临时目录里的便携版，
> 电脑重启后可能就没了。没有也别卡着——照常推，我这边会跑。

## 目录速查：想改什么，动哪个文件

| 想改什么 | 动哪个文件 |
|---|---|
| 首页上写死的文案 | `index.html` |
| 杂谈 / 作品 / 练琴 / 联系方式的**内容** | `scripts/site-data.js` |
| 杂谈页的分类标签 | `scripts/site-data.js` 的 `essayTags`（现在是空的，所以没有筛选栏） |
| 作品页那五类 | `scripts/site-data.js` 的 `workTags`（顺序就是按钮顺序） |
| 所有页面的**视觉**（配色、边框、间距、字号） | `assets/style.css`（只改开头 `:root` 那一块） |
| 全站字号整体放大缩小 | `assets/style.css` 里的 `--text-scale` |
| 首屏那张图 | `assets/banner.svg` |
| 导航栏、页脚（六个页面都要改） | 五个 `.html` 各改一次 |
| 明暗开关的行为、按钮文案 | `scripts/theme.js` |
| 留言墙接哪个后端 | `index.html` 顶部的 `window.GUESTBOOK_CONFIG` |
| 《Jary行为研究》期刊 | `Jary/` 目录，跟主站完全独立，两边互不影响 |

**杂谈、作品、练琴这三块的列表是脚本渲染出来的**，内容都在 `scripts/site-data.js` 里。
在那边加一条，页面上自己就会出现——不用碰 HTML。

**分类筛选是「先声明、后归类」**：

- 作品的五个分类写在 `workTags` 里，顺序就是按钮顺序。加新作品时，把 `tag`
  写成这五个之一，它就归到那一类；tag 不在清单里的作品只在「全部」里出现。
- 杂谈的 `essayTags` 现在是空数组，所以杂谈页没有筛选栏，就是一条时间线。
  以后想分类了，往里写分类名（`essayTags: ['随笔', '项目']`），按钮会自己长出来，
  再给对应文章的 `tag` 写上同样的名字就行。清单里先摆一个还没内容的分类也可以，
  它会显示 0 篇。
